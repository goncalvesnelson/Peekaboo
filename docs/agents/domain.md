# Domain docs

Peekaboo uses one domain context. Read the root `CONTEXT.md` and relevant records in `docs/adr/` before exploring the codebase. If these files do not exist, continue without creating placeholders.

`CONTEXT.md` is a glossary of resolved domain terms, not an implementation plan. Use its vocabulary in code, issues, and discussion. Add terms as they are agreed through `domain-modeling` or `grill-with-docs`.

Store architecture decision records under `docs/adr/`. Create one only for an agreed decision that is hard to reverse, surprising without context, and based on a real trade-off. Flag conflicts with an existing decision before changing it.
